# TranslationBridge Architecture

## Status

Draft

---

# Motivation

Библиотека предназначена для построения систем синхронного речевого перевода.

Основная цель — предоставить простой API для организации двустороннего (или многостороннего) перевода между произвольными источниками и получателями аудио.

При проектировании было принято решение разделить библиотеку на два уровня:

- низкоуровневый API (`core`, `providers`)
- высокоуровневый API (`TranslationBridge`)

---

# Основная идея

Высокоуровневый API строится вокруг объекта `TranslationBridge`.

`TranslationBridge` не выполняет перевод самостоятельно.

Он является контейнером для независимых линий перевода (`TranslationLine`) и отвечает только за их совместную работу.

```
                    TranslationBridge

        +--------------------------------------+
        |                                      |
        |   TranslationLine                    |
        |   TranslationLine                    |
        |   TranslationLine                    |
        |   ...                                |
        +--------------------------------------+
```

---

# TranslationLine

`TranslationLine` представляет собой независимый поток перевода.

Каждая линия имеет собственные:

- Client
- Provider
- Realtime Session
- настройки модели
- целевой язык
- голос
- аудио-вход
- аудио-выход

Линия ничего не знает о существовании других линий.

---

# Целевой язык

Линия задаёт только целевой язык перевода.

Например

```rust
TranslationLine {
    target_language: Language::English,
}
```

Исходный язык модель определяет автоматически.

Это соответствует поведению OpenAI Realtime API.

---

# TranslationBridge

Bridge создаёт и управляет линиями.

Предлагаемый API:

```rust
let bridge = TranslationBridge::new();

let english = bridge.add_line(Language::English);
let russian = bridge.add_line(Language::Russian);
```

Возвращаемый объект представляет собой handle линии.

Например

```rust
english.attach_in(...);

english.attach_out(...);

russian.attach_in(...);

russian.attach_out(...);

bridge.start();
```

---

# Почему не две линии?

Изначально рассматривалась архитектура

```
Bridge
 ├── left
 └── right
```

Однако она искусственно ограничивает систему двумя участниками.

Использование произвольного количества линий позволяет естественно поддерживать:

- двусторонний перевод;
- конференции;
- вещание сразу на несколько языков;
- запись нескольких потоков;
- подключение новых участников.

---

# Ответственность объектов

## TranslationBridge

Отвечает за:

- создание линий;
- управление жизненным циклом;
- маршрутизацию между линиями;
- запуск и остановку системы.

Не отвечает за:

- перевод текста;
- работу модели;
- обработку аудио.

---

## TranslationLine

Отвечает за:

- соединение с AI Provider;
- поток аудио;
- получение перевода;
- синтез речи;
- собственное состояние.

Не знает о других линиях.

---

# Масштабируемость

Архитектура позволяет естественным образом расширять систему.

Например

```
              English
                  ▲
                  │
Russian ◄── TranslationBridge ──► German
                  │
                  ▼
               Japanese
```

Без изменения публичного API.

---

# Итоговая идея

`TranslationBridge` представляет собой контейнер независимых линий перевода.

Количество линий не ограничено.

Каждая линия является полностью самостоятельной единицей обработки речи.

Такое разделение позволяет сохранить простой API библиотеки и избежать искусственных ограничений на количество участников или языков.
